# QRコード照合＆スプレッドシート記録システム (QR Matching & Sync)

このアプリケーションは、ChromebookやPCのブラウザから内蔵カメラを利用して2つのQRコードをスキャンし、それらが一致するかどうかを照合判定し、スプレッドシートへの記録および画面への結果表示を行う検品・お渡し用システムです。

---

## ✨ 本アプリの特別仕様

### 1. チェックデジットの自動除外（照合ロジック）
- **QRコードA (手持ち用)**: 参加者が手にするチェックデジット付きのコード（例: `M83810-1`, `M28893-4`, `M82397-X`）。
- **QRコードB (完成品用)**: 作品に貼り付けられているチェックデジットなしのコード（例: `M83810`）。
- **照合ルール**: 自動的にハイフン `-` 以降を除外（例: `M83810-1` ➡️ `M83810`）し、完成品コードとクリーンな値同士で一致するかを比較します。

### 2. スプレッドシート連携（「フォームの回答 1」）
照合が一致（OK）した場合、Google Apps Script (GAS) を経由してスプレッドシートの **「フォームの回答 1」** シートから該当のQRコード行を高速検索し、以下の自動処理を行います。
- **お渡し完了時刻の記録**: 該当行の **N列（14列目）** に現在日時（JST）を自動で書き込みます。
- **作品データ・画像の取得**: **D列（4列目）** から「お名前」を、**T列（20列目）** から「jpg」（Googleドライブの共有URL）を取得し、ブラウザアプリに返却します。

### 3. 作品受領Logシートへの自動記録
照合結果（一致・不一致に関わらずすべて）は、スプレッドシートに **「作品受領Log」** シートを自動生成し、以下の項目をタイムスタンプ付きで記録します。
1. **タイトル（お名前）** （※一致した場合はマスターのお名前、不一致時は無し）
2. **タイムスタンプ**
3. **判定結果** （一致 / 不一致）
4. **読取りデータ1** (QR_A の生データ、例: `M83810-1`)
5. **読取りデータ2** (QR_B の生データ、例: `M83810`)
6. **端末名/担当者** (設定で指定した値)
- ※ 不一致の場合はログ行が薄い赤色に自動着色され、不一致が一目で分かります。

### 4. 画面への大型表示フィードバック
- **照合OK (一致)**:
  - 画面中央に大きくモーダルが表示され、「お名前」および **作品のサムネイル画像** がダイナミックに表示されます。
  - Googleドライブの共有用URLは自動的に直接表示可能な画像リンクに変換されます。
- **照合NG (不一致)**:
  - 画面全体に赤ベースで **『残念！ 不一致です。 他の作品を探してください』** と大きく警告メッセージが表示されます。

## 🛠️ セットアップ手順

スプレッドシートへの記録を有効にするために、以下のGAS設定を行います。

### 1. Google スプレッドシートの作成
1. マスターデータ（シート名: `フォームの回答 1`）が存在する **Google スプレッドシート** を開きます。
2. 上部メニューの **[拡張機能]** > **[Apps Script]** をクリックしてエディタを開きます。

### 2. GASコードの貼り付け
1. エディタ内の既存コードをすべて削除し、本プロジェクトの **[gas-template.js](file:///g:/共有ドライブ/KiriPlayPark/Tool/Antigravity/kiriplaypark-projects/久喜イノベーションの会/QrMatching/gas-template.js)** のコードを貼り付けます。
2. エディタ上部の「保存」アイコンを押します。

### 3. ウェブアプリとしてデプロイ
1. 右上の **[デプロイ]** > **[新しいデプロイ]** をクリック。
2. 歯車マークから **「ウェブアプリ」** を選択。
3. 各設定を以下のように指定します：
   - **次のユーザーとして実行**: `自分 (スプレッドシートのオーナー)`
   - **アクセスできるユーザー**: `全員` (Chromebookから認証なしで書き込むために必須)
4. **[デプロイ]** ボタンをクリック。
5. Googleアカウントを選択し、[詳細] > [ウェブアプリ名（安全ではないページ）に移動] を選択して、権限を承認します。
6. 発行された **「ウェブアプリ URL」** をコピーします。

### 4. ブラウザアプリ側の設定
1. 作成した `index.html` をブラウザで開きます（下記の「実行方法」を参照）。
2. 右上の **[設定]** ボタンをクリック。
3. コピーした **「Google Apps Script (GAS) Web App URL」** を貼り付けます。
4. **「端末名 / 担当者名」**（ログの送信元として記録されます）や、判定後の自動閉じる待機時間（「マッチ判定後の自動リセット時間」: 初期値2秒）を調整し、**[設定を保存する]** をクリックします。

## 🚀 実行方法とカメラの注意点 (重要)

ブラウザ上でカメラを使用する機能（`getUserMedia` API）は、セキュリティ仕様上、**セキュアコンテキスト（HTTPS接続、または localhost）で動作している必要があります。**

> [!WARNING]
> ローカルで単に `index.html` ファイルをダブルクリックして `file://...` スキームとしてブラウザで直接開いた場合、カメラの権限ダイアログが表示されず、カメラが起動しないことがあります。

### 実行方法

#### A. ローカル開発サーバーを起動して使用する（推奨）
PCやChromebook上で、簡易的なローカルサーバーを起動することで、`http://localhost` 経由でアクセスし、カメラを正常に動作させることができます。

1. コマンドプロンプトやPowerShellを開きます。
2. `npx` コマンドを使用して、プロジェクトフォルダでサーバーを起動します：
   ```bash
   npx serve .
   ```
3. 画面に表示されるローカルURL（通常は `http://localhost:3000` など）にブラウザでアクセスします。これでカメラが機能します。

#### B. 外部のセキュアなWebサーバー（HTTPS）に配置する
本番運用する際は、レンタルサーバーや、GitHub Pages、あるいは社内イントラネットのHTTPS化されたサーバー上に `index.html`, `style.css`, `app.js` を配置してアクセスしてください。

## 🔄 照合フロー（使い方）

1. アプリを起動し、右上の **[カメラ起動]** ボタンを押します（カメラの使用許可が出たら承認してください）。
2. **1. 照合元 (QRコードA)**（手持ち用: チェックデジット付き）をスキャンします。
3. **2. 照合先 (QRコードB)**（完成品用）をスキャンします。
4. 照合完了後、自動的に判定結果ダイアログが表示されます：
   - **一致 (MATCH)**: 
     - 「照合一致！お渡しできます」と表示され、ローディングスピナーの後、マスターに登録されている **お名前** と **作品のサムネイル画像** がポップアップで大きく表示されます。
     - スプレッドシートの「フォームの回答 1」の該当行の **N列（1渡し完了時刻）** に現在時刻が書き込まれます。
     - 「作品受領Log」シートに「一致」のログが保存されます。
   - **不一致 (MISMATCH)**: 
     - 画面が赤ベースになり、**「残念！ 不一致です。他の作品を探してください」** と大きく警告メッセージが表示されます。
     - 「作品受領Log」シートに「不一致」のログが保存されます。
5. 設定した自動リセット時間が経過するか、モーダルの **[閉じる]** ボタン（またはキーボードの **Escapeキー**）を押すと、モーダルが閉じ、自動的に「1. 照合元」の次のスキャン待機状態にリセットされます。
